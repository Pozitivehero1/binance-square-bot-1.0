# Binance Square Bot 3.0 — Content Diversity

Workflow `.github/workflows/run.yml` не изменён. Ключи и способ публикации остаются прежними.

## Главная переработка

Раньше несколько вариантов поста отличались в основном заголовком, CTA и порядком одинаковых блоков. Поэтому публикации выглядели как один шаблон с другими числами.

Теперь вариативность разделена на два независимых уровня:

- **Тип рыночного сигнала:** пробой, откат, снятие ликвидности, продолжение тренда, повышенный объём, MTF-согласованность, контроль VWAP, работа у границы диапазона, моментум и расширение волатильности.
- **Формат публикации:** рыночная заметка, сначала цифры, два сценария, чек-лист, фокус на уровне, тезис и аргументы, сначала риск, короткий бриф.

Каждый тип сигнала выбирается только тогда, когда он подтверждается рассчитанными индикаторами. Ради разнообразия бот не выдумывает события.

## Что изменено

- Добавлен классификатор реальных рыночных сетапов в `content_variation.py`.
- Генерация одного запуска теперь исследует до 8 разных компоновок и до 6 разных акцентов.
- По умолчанию `POST_VARIANTS=8` вместо 5.
- В историю сохраняются `post_style` и `signal_type`.
- Повторяющиеся типы сигналов получают штраф при выборе следующей монеты.
- Текст сравнивается как с историей публикаций, так и с другими вариантами текущего запуска.
- Слишком похожий вариант не выигрывает только за счёт формального quality score.
- Переработан quality evaluator: новые форматы больше не штрафуются за отсутствие одного фиксированного шаблона.
- Добавлены 4 визуально разные карточки: dashboard, ladder, scenario split и risk-first.
- На карточке теперь отображается конкретный тип сетапа.
- AI-полировка, если включена, обязана сохранять выбранный формат и рыночный акцент.

## Безопасность сигнала сохранена

- Используются только фактические индикаторы и рассчитанные уровни.
- Вход, TP1, TP2, TP3, стоп и реальный R/R обязательны.
- BTC/funding-фильтры и hard gates не ослаблены.
- Нет заявлений о гарантированной прибыли, китах или вероятности успеха.
- Сценарий всегда содержит точку отмены и напоминание о размере позиции.

## Проверка

```bash
pip install -r requirements.txt
python self_test.py
```

Тест проверяет:

- LONG и SHORT;
- расчёт уровней;
- качество текста;
- генерацию карточки и графика;
- минимум 7 разных форматов;
- минимум 5 разных рыночных акцентов;
- отсутствие почти одинаковых вариантов.

Для запуска без публикации:

```bash
DRY_RUN=1 python main.py
```

## Основные переменные

- `POST_VARIANTS=8` — число вариантов контента перед выбором лучшего.
- `MIN_POST_QUALITY=72` — минимальная оценка публикации.
- `POST_MAX_CHARS=1600` — максимальная длина.
- `MIN_SIGNAL_SCORE=54` — минимальный итоговый скор сетапа.
- `MIN_RR=1.5` — минимальный реальный R/R.
- `STRICT_BTC_FILTER=1` — не публиковать сетап против сильного движения BTC.
- `ENABLE_AI_POLISH=0` — детерминированный текст без внешнего AI по умолчанию.

## Adaptive signal selection update

- Strict publication gates remain the first and preferred pass.
- If no strict candidate exists, an optional balanced pass accepts only near-threshold setups.
- Balanced mode still requires a positive risk/reward ratio, at least two higher timeframes,
  usable ATR/ADX, multi-timeframe confirmation and non-dead relative volume.
- The log now explicitly shows `Signal selection profile: strict|balanced`.
- Bybit fallback is disabled by default because US-hosted runners can receive HTTP 403.
  It can be re-enabled with `ENABLE_BYBIT_FALLBACK=1` on a compatible host.
