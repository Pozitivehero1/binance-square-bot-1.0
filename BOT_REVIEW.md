# Технический аудит Attention Edition

## Главная исправленная ошибка

Прошлая Distribution Edition ошибочно пыталась решить низкие просмотры ограничением частоты. В этой версии частоту снова задаёт внешний cron. При `ENABLE_PACING_LIMITS=0` старые значения `MIN_GLOBAL_INTERVAL_MIN=120` и `MAX_POSTS_PER_DAY=6` не влияют на публикацию.

## Что теперь влияет на выбор темы

Бот больше не выбирает монету только по качеству технического сетапа. Для каждого кандидата рассчитывается текущий attention-score:

- изменение последней закрытой 15M-свечи;
- изменение за 45 минут;
- объём последней 15M-свечи относительно медианы предыдущих 20;
- расширение диапазона свечи;
- оборот в USDT за последний час;
- соответствие свежего движения направлению сетапа;
- штраф за поздний вход при растянутом RSI или сильном удалении от EMA20.

Финальный кандидат выбирается по сочетанию технического качества и текущего внимания. Это не гарантирует охват, но устраняет ситуацию, когда бот публикует спокойный или уже отработавший график только потому, что индикаторы выглядят аккуратно.

## Контент

Не каждый пост теперь обязан выглядеть как одинаковый торговый сигнал с полным набором `Вход / TP1 / TP2 / TP3 / Стоп / R/R`.

Есть два типа контрактов:

- полный торговый план;
- компактный feed-пост с текущим движением, всплеском объёма, ключевым уровнем, TP1 и точкой отмены.

Для активного рынка добавлен `pulse_card`: крупное изменение за 15 минут, свежий объём, ключевой уровень и attention-score. На мобильном экране эта карточка читается быстрее старых перегруженных таблиц.

## Cron

Штатная команда:

```bash
python /absolute/path/run_bot.py
```

Рекомендуемая настройка пользователя:

```env
ENABLE_PACING_LIMITS=0
ENABLE_REACH_GATE=0
COOLDOWN_MIN=180
```

Cron можно оставить `*/20 * * * *`.

## Ограничения

Бот не получает просмотры и другие метрики публикаций из Binance Square, поэтому не может автоматически обучаться на фактическом CTR или охвате. Attention-score основан на рыночных данных, а не на внутренней аналитике Square.
