# Аудит и исправления

## Найденные причины шаблонности

1. `MISTRAL_API` передавался в GitHub Actions, но AI-полировка была отключена через `ENABLE_AI_POLISH=0` по умолчанию.
2. Даже при включении Мистрал только переписывал уже собранный шаблон, поэтому структура и служебные фразы сохранялись.
3. Генератор перебирал до 30 больших шаблонов, создавая много текста, но не настоящую авторскую подачу.
4. Тестовые посты имели среднюю длину около 992 знаков и содержали повторяющиеся блоки контекста, риска и CTA.
5. Quality score поощрял длину до 1300 знаков и наличие большого количества блоков.
6. В footer использовалось четыре хэштега, усиливая ощущение автоматической публикации.
7. Локальный `.env` не загружался, несмотря на наличие `python-dotenv` в зависимостях.
8. Workflow запускался только вручную и не имел расписания.
9. График был широким и перегруженным пересекающимися подписями уровней и индикаторов.

## Реализованное решение

- AI-first batch generation через один запрос к Mistral JSON mode.
- Закрытый каталог фактов и выбор `fact_ids` вместо свободного создания рыночных данных.
- Свободные AI-поля не могут содержать цифры, тикеры или хэштеги.
- Код-контракт для тикера, входа, целей, стоп-лосса и R/R.
- Числовой allowlist: неизвестные числовые факты блокируются.
- Автоматический короткий fallback при сбое Mistral.
- Расширенный комбинаторный fallback устраняет повторение прежнего восьмипостового цикла.
- Антидубликат сравнивает каждый кандидат с последними 100 постами; жёсткий порог снижен до 0.45.
- Новая целевая длина 380–780 знаков, жёсткий предел 900.
- Не более двух хэштегов и ровно один вопрос.
- Один мобильный график с отдельной панелью уровней.
- Строгие сигналы по умолчанию; balanced fallback выключен.
- Три плановых запуска GitHub Actions в день и защита от параллельных запусков.
- Workflow переведён на Node.js 22 для совместимости с актуальным установщиком Binance Skills Hub.
